# Widget parameters

Every served type of the widget API (`docs/widget-api.md`, *Parameters*), every key it accepts --
exactly the backticked keys of its catalogue **Parameters** paragraph (`docs/widget-catalogue.md`) --
its class and its default. `data` keys are applied: two values give two different responses.
`rendering` keys are accepted, echoed in `parameters`, and never applied. `none` is an absent default:
an empty optional list means no restriction. A test of the repository holds this table equal to the
code (`internal/widget/widgets/catalogue_test.go`), so it cannot drift from what is served.
